\section{Developer-Dokumentation}\label{sec:developer_doku}

Diese Anleitung beschreibt die Installation des Projekts und die Ausführung seiner Komponenten.
Damit soll das Projekt für Dritte reproduzierbar und nachvollziehbar sein.

\subsection{Installation}

Zum Einstieg werden das Repository geklont und die Abhängigkeiten installiert.

\begin{lstlisting}[language=bash]
git clone https://github.com/Miedefran/CounterfactualRegretMinimizationPoker
\end{lstlisting}

Die Abhängigkeiten werden mit \texttt{uv sync} installiert:

\begin{lstlisting}[language=bash]
uv sync
\end{lstlisting}

\subsection{Ausführung}

Über die TUI (Text User Interface) lassen sich die Komponenten des Projekts starten.
Die Startbefehle unterscheiden sich, je nachdem ob \texttt{mise} installiert ist oder nicht.

Mit \texttt{mise}:
\begin{lstlisting}[language=bash]
mise run tui
\end{lstlisting}

Ohne \texttt{mise}:
\begin{lstlisting}[language=bash]
uv run python src/tui/app.py
\end{lstlisting}

\subsection{Human vs Human Modus}

Im Modus Human vs Human spielen zwei Spieler über einen Server gegeneinander.
Nach dem Start der TUI öffnet sich der Multiplayer-Tab; dort lassen sich Server und Client konfigurieren.
\newpage
\begin{figure}[h]
\centering
\includegraphics[width=0.85\textwidth]{tui_multiplayer.png}
\caption{TUI Multiplayer-Interface mit Server- und Client-Konfiguration}
\label{fig:tui_multiplayer}
\end{figure}

Die Oberfläche gliedert sich in die Bereiche Server und Client.
Im Server-Bereich sind Spiel (Dropdown), Port (Eingabefeld) und Host (Dropdown) einstellbar.
Über \enquote{Start Server} und \enquote{Stop Server} wird der Server gestartet bzw.\ gestoppt.
Im Status-Bereich werden Laufstatus, lokale IP-Adresse für Remote-Verbindungen und die Connection-URL angezeigt.
Im Client-Bereich startet \enquote{Start Local Client} einen lokalen Client.
Für Remote-Verbindungen sind Server-IP, Port und Spielername in den jeweiligen Feldern einzutragen; \enquote{Start Remote Client} startet den Remote-Client mit diesen Einstellungen.

Sind Server und beide Clients gestartet, öffnet sich pro Spieler ein GUI-Fenster.
Jeder sieht das Spiel aus seiner Perspektive inklusive eigener Karten und Aktionsbuttons.

\centering

\caption{Multiplayer GUI - Perspektive Spieler 1 (verlierende Hand)}
\label{fig:multiplayer_p1}
\end{figure}

\begin{figure}[h]
\centering
\includegraphics[width=0.85\textwidth]{multiplayer_perspective2.png}
\caption{Multiplayer GUI - Perspektive Spieler 2 (gewinnende Hand)}
\label{fig:multiplayer_p2}
\end{figure}

Die GUI zeigt einen Pokertisch mit grünem Filzhintergrund.
In der Mitte liegen die Board Cards (Community Cards), die für alle Spieler sichtbar sind.
Links daneben erscheinen der aktuelle Pot als Zahl und Chip-Stapel zur Darstellung des Pot-Betrags.

Oben im Fenster ist der Gegenspieler dargestellt (im Multiplayer der andere menschliche Spieler).
Dessen Karten werden erst nach Ende der Hand aufgedeckt.
Darunter wird die Handstärke angezeigt (z.\ B.\ \enquote{High Card}, \enquote{Pair}, \enquote{Two Pair}, \enquote{Straight}).

Unten erscheinen die eigenen Hole Cards und die zugehörige Handstärke.
Darunter liegen die Aktionsbuttons \enquote{Check}, \enquote{Bet}, \enquote{Call} (mit zu zahlendem Betrag) und \enquote{Fold}; sie sind nur aktiv, wenn der Spieler am Zug ist.

Rechts oben befinden sich \enquote{New Hand} für eine neue Hand und \enquote{Beenden} zum Beenden des Spiels.
Darunter listet der History-View alle Aktionen der aktuellen Hand chronologisch auf.
Am Handende werden Ergebnis (z.\ B.\ \enquote{You wins 100!} bzw.\ \enquote{Opponent wins 100!}) und Payoff-Informationen angezeigt.

\subsection{Agent vs Human Modus}

Im Modus Agent vs Human spielt ein Mensch gegen einen trainierten Agenten.
Vor dem ersten Spiel muss eine Strategie für das gewählte Spiel trainiert werden.
Dafür kann ein beliebiger Algorithmus genutzt werden; empfohlen wird \texttt{discounted\_cfr\_with\_flat\_tree}, da er die stärksten Ergebnisse liefert.

Für die Spielauswahl gelten zwei Empfehlungen.
Bei wenig Zeit eignet sich \texttt{twelve\_card\_poker}, da es schneller trainiert.
Bei mehr Zeit empfiehlt sich \texttt{small\_island\_holdem}; es ist komplexer und benötigt längere Trainingszeiten.
Beide Spiele stammen aus dieser Arbeit; die genauen Regeln stehen im Anhang der Bachelorarbeit im Ordner \texttt{latex/thesis}.

Das Training wird in der TUI im Tab \enquote{Training Queue} konfiguriert.
Dort lässt sich ein neuer Training Task anlegen; dabei sind Spiel, Algorithmus, Iterationsanzahl und weitere Parameter wählbar.
Über \enquote{Early Stop Exploitability} kann das Training automatisch beendet werden, sobald ein vorgegebener Exploitability-Wert erreicht ist, was Zeit spart, sobald die Strategie ausreichend gut ist.

Den Trainingsverlauf zeigt der Tab \enquote{Current Task}.
Dort erscheinen Fortschritt, verstrichene und geschätzte verbleibende Zeit sowie eine Tabelle mit Best-Response-Evaluations.
An diesen Metriken lässt sich prüfen, ob das Training wie erwartet läuft und die Exploitability-Werte sinken.

Nach dem Training kann im Tab \enquote{Models} ein trainiertes Modell zum Spiel gegen den Agenten ausgewählt werden.
Eine veraltete Modellliste wird mit \texttt{r} aktualisiert.
Nach Anklicken eines Modells startet \texttt{g} das Spiel; das GUI-Fenster öffnet sich automatisch.
