\section{Theoretische Grundlagen}\label{sec:hintergrund}


\subsection{PyQt6}

\textbf{PyQt6} wurde als GUI-Framework gewählt, da es das Signal-Slot-Pattern unterstützt und damit lose Kopplung zwischen Komponenten ermöglicht.
Ein weiterer Grund für die Wahl war, dass im Rahmen eines anderen Moduls bereits mit Qt in C++ gearbeitet wurde und viele Konzepte daher vertraut waren.

Das Signal-Slot-Pattern ist ein zentrales Konzept von PyQt6 und implementiert das Observer-Pattern.
Signale werden mit \texttt{pyqtSignal} definiert und von Komponenten emittiert, ohne dass der Emittent weiß, wer sie empfängt.
Slots sind die Methoden, die an Signale gebunden werden.
Damit lassen sich Komponenten unabhängig voneinander entwickeln und testen.

\textbf{QTimer} ermöglicht verzögerte Ausführung, ohne die GUI zu blockieren.
Eingesetzt wird es unter anderem, um Initialisierungsschritte zu verzögern oder Aktionen des Agenten mit einer kurzen Pause auszuführen.

\textbf{QPainter} dient dem Custom Painting, also dem Zeichnen eigener Grafiken.
So wird etwa der Pokertisch in der \texttt{paintEvent()}-Methode implementiert.

Über \texttt{setStyleSheet()} lassen sich Widgets mit CSS-ähnlicher Syntax gestalten, etwa Farben, Rahmen und weitere visuelle Eigenschaften.
Die Spielkarten nutzen Stylesheets für das Styling der Widgets, der Inhalt wird über HTML gerendert.

\subsection{Netzwerk-Kommunikation}

Für die Echtzeit-Kommunikation im Multiplayer-Modus kam zunächst \textbf{HTTP} mit Polling zum Einsatz.
Dabei muss der Client den Server regelmäßig abfragen, um Updates zu erhalten.
Daraus folgt eine Mindestlatenz in Höhe des Pollingintervalls (z.\,B.\ 100\,ms) sowie unnötiger Netzwerkverkehr, selbst wenn keine Änderungen anstehen.
Hinzu kommt, dass die Kommunikation unidirektional ist.
Der Client fragt an, der Server antwortet.
Der Server kann jedoch nicht proaktiv Updates senden.

Als Verbesserung wurde \textbf{WebSocket} implementiert, das nun als Standard dient.
WebSocket ermöglicht bidirektionale Kommunikation mit Push und geringer Latenz.
Der Server kann Clients Updates unmittelbar zustellen, sobald sie verfügbar sind, ohne dass diese regelmäßig anfragen müssen.
Dadurch sinkt die Latenz deutlich und die Spielerfahrung verbessert sich, da State-Updates praktisch sofort ankommen.
HTTP bleibt als Fallback verfügbar.

Für beide Protokolle ist \textbf{SSL/TLS-Verschlüsselung} vorgesehen, um die Kommunikation zu schützen.
HTTPS (HTTP) und WSS (WebSocket) ermöglichen verschlüsselte Verbindungen.
Daten können während der Übertragung weder abgefangen noch manipuliert werden.
Besonders relevant ist das, wenn der Server über das Internet erreichbar ist.

\subsection{Asynchrone Programmierung}

\textbf{asyncio} kommt für die WebSocket-Kommunikation zum Einsatz, da die \texttt{websockets}-Bibliothek darauf aufbaut.
Asynchrone Programmierung erlaubt nicht blockierende Netzwerkoperationen.
Der Thread muss nicht auf Antworten warten, sondern gibt die Kontrolle an die Event-Loop zurück, bis die Operation abgeschlossen ist.

Das Problem besteht darin, dass Qt-Anwendungen eine eigene Event-Loop für GUI-Updates nutzen, asyncio hingegen eine separate benötigt.
Würde asyncio direkt im GUI-Thread laufen, blockierte dies die Oberfläche.
Gelöst wird das durch einen \texttt{QThread} mit eigener asyncio-Event-Loop.
Die Klasse \texttt{WebSocketWorker} erbt von \texttt{QThread} und startet in \texttt{run()} eine neue asyncio-Event-Loop.
Über PyQt6-Signale werden asynchrone Ereignisse in den GUI-Thread übermittelt.
Asynchrone Netzwerkkommunikation und GUI-Updates bleiben so sauber getrennt.

\subsection{Testing}

\textbf{pytest} wurde als Testing-Framework gewählt, da es Fixtures für wiederverwendbare Testsetups bietet und gegenüber \texttt{unittest} eine klarere Testorganisation sowie lesbarere Syntax aufweist.
Fixtures erlauben wiederverwendbare Setups, die sich in mehreren Tests nutzen lassen.
So kann etwa eine Fixture einen Server auf einem dynamischen Port starten und ihn mehreren Tests bereitstellen.

Für asynchrone WebSockettests kommt \textbf{pytest-asyncio} zum Einsatz.
Es erlaubt \texttt{async def}-Testfunktionen und verwaltet die asyncio-Event-Loop automatisch.
\textbf{unittest.mock} dient dem Mocking, unter anderem um zeitabhängige Tests deterministisch zu gestalten.
